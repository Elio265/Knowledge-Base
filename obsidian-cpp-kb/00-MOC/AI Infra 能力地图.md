# AI Infra 能力地图

> **用途**：[[职业规划与准备]] Phase 0/1 的执行验收清单——每项只回答"学什么 + 到什么程度算够"。
> 原则：**先对验收标准，再谈学习量**；够线以下不加时间，够线以上留给上岗后。

## 一、第一梯队：面试生死线（2026.09–2027.03）

### ① 推理栈全景 + 一个深入点

- [ ] 画出"一个请求从进入推理服务到吐完 token"的完整数据流（continuous batching、PagedAttention、prefill/decode 分离），合上资料验证
- [ ] 能逐步解释瓶颈：compute-bound vs memory-bound、KV cache 什么时候撞显存墙
- [ ] vLLM 或 SGLang 亲手部署 7B，做一轮 batch × 序列长度压测
- [ ] 讲得清吞吐/延迟/成本三条曲线的形状和原因
- [ ] 产出压测小复盘一篇 → 进 Phase 1 文章候选

> [!tip] 存储人的捷径
> KV cache ≈ 页缓存；continuous batching ≈ I/O 调度合并；prefill/decode 分离 ≈ 顺序读 vs 随机读。用存量概念挂钩，学习量减半。

### ② AI 负载 × 存储交叉判断力（差异化武器）

- [ ] 3FS 架构文档精读，能连讲 30 分钟
- [ ] 梳理三类负载画像：checkpoint 写风暴 / 训练数据集高吞吐读 / 向量检索存储底座
- [ ] 备好话术："如果 EDS 接 AI 训练场景我会怎么改"（带宽 vs 元数据 vs 一致性的取舍）
- [ ] 跟踪 KV cache 分级 offload（SSD）趋势并形成自己观点

### ③ LLM 网关 / 平台组件

- [ ] SangBridge 演进版落地其一：token 计量 或 Redis 分布式限流（与 Phase 0 同一件事，别重复排期）
- [ ] 理解流式转发（SSE/WebSocket）与多模型路由、故障转移的设计模式
- [ ] 了解评测（evals）流水线做法：能对比两个开源评测框架
- [ ] 所有取舍写回 [[SangBridge AI统一接入与管理控制台]]：为什么选 / 代价 / 下一步演进

### ④ 系统设计表达（AI 场景）

- [ ] 建题集：模型服务平台 / 分布式限流器 / 向量检索服务 / 训练数据管道
- [ ] 每题写方案提纲：约束 → 分层 → 容量 → 瓶颈 → 演进
- [ ] 真实演练 ≥3 场（用模考），每场复盘进 [[职业规划与准备]]
